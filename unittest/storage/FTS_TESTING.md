# 全文索引候选优化

2026-10-29 交接复核：`183cac5a8` 的“全局解析器缓存 + TLS token map”已由 `d3833a7d1` 撤销。该提交未做实际构建和性能验证，不能接受其 26 倍提速、停顿消除或预计得分的声明。

撤销依据：全局缓存保存由调用方 allocator 分配的可变解析器，但该 allocator 随查询结束失效；互斥锁仅覆盖缓存查找/插入，不覆盖 reuse、分词和迭代器消费，因此并发查询会共享并重置解析器状态；init 失败时删除已存入缓存的对象却不移除缓存项。TLS token map 同样保留调用方 allocator 和其中对象，跨查询访问可能使用已失效内存。原先已验证的停用词及重复词聚合改动仍保留。

3 秒停顿的根因仍未查明。构造/释放解析器是值得测量的热点，不是停顿原因的证据。后续性能报告须来自同机、同参数、无并行编译的官方脚本，并保留原始样本和正确性核验。

当前状态：完整 seekdb 构建及 4 项正确性回归通过。微基准和官方脚本已实际运行；官方查询耗时有明显波动，尚不能认定整体提速或本题完成。

## 改动

- 重复词频聚合：已存在的词直接更新文档私有词表中的计数，减少一次哈希及比较；首次插入、词表比较规则和错误返回保留原行为。
- 停用词：输入和字典排序规则完全相同时直接查询；其他排序规则继续转换，并在转换缓冲区释放之前完成查询。

测试覆盖重复词精确计数、增加已有词的频率、大小写不敏感排序规则、未初始化词表的错误，以及不同排序规则下的停用词结果。

## 验证入口

```sh
cmake --build build_release --target fts_word_regression fts_word_benchmark -j2
ctest --test-dir build_release -R '^fts_word_regression$' --output-on-failure
./build_release/unittest/fts_word_benchmark
```

微基准调用生产 `ObAddWord::process_word`，处理 400 万个词，并在输出耗时前核对全部计数。它只测重复词聚合热点，不能替代官方全文索引测试或用于宣称比赛得分。

正式性能验证应使用未修改的 `tools/benchmark/fts_large_bench.sh`，在独立测试实例上保存优化前后原始报告。两个版本保持编译方式、机器资源和测试参数一致；运行基准时不并行编译。完整核对建索引、分词和查询三组指标，以及分词和查询结果。官方脚本会重建自己的测试库，应只用于测试实例。

## 2026-10-26 实测

WSL Ubuntu 24.04、Clang 17、Release；基线为官方 `5bce9e06d1281347ad61344e4b01fab9158c58a2` 的 FTS 实现，候选为本仓库 `ca9e563` 的 FTS 实现。两个可执行程序包含相同 AI 改动，仅切换 `ob_fts_stop_word.cpp`。构建镜像来自压缩包、没有 `.git`，因此原始报告的 `git_head=unknown` 不能作为版本标识。

400 万词微基准各运行 5 次，中位数由 603828076 ns 降到 275797278 ns，约 2.19 倍，仅代表重复词聚合热点。逐次原始数据见 `fts_word_measurements.json`。

官方脚本使用默认 20000 行、3 次样本、30 次预热、3000 次分词及 200 次查询，在同一独立原生实例端口 2882 执行；基线和候选运行期间均未并行编译。时间如下：
